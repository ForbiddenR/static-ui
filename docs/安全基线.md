<a id="security-baseline"></a>
## 安全与敏感信息规则

> [本节角色]
> 本节定义跨层最低安全要求。资源文档中的鉴权、脱敏和存储限制是本节规则的场景化应用；如局部摘要与本文件冲突，以本文件为准，并在 [待对齐问题](待对齐问题.md#alignment-issues) 登记差异。

<a id="token-boundary"></a>
### 身份与令牌边界

第一版安全边界：

```text
SDK 不直接访问 Master
脚本不需要 Master 地址
脚本不持有 Master 管理权限
SDK / Worker Runtime 使用短期任务级 TASK_TOKEN
TASK_TOKEN 只能访问当前 Task
Task 完成 / 取消 / 超时后 TASK_TOKEN 失效
Worker 使用 worker_token 或 shared_secret 连接 Master
```

补充要求：

1. `TASK_TOKEN`、`worker_token`、`shared_secret` 和用户访问令牌只能通过受控配置、进程注入或认证消息传递，不得进入业务 payload。
2. Worker 的认证凭据只用于建立或恢复受控会话；协议消息是否携带凭据以 [Worker 协议](Worker协议与运行时.md#worker-protocol) 为准。
3. 通知目标不应在脚本中硬编码 webhook，应通过受控 `channel` 引用。
4. `secrets` 模块用于按授权读取密钥，脚本不直接读取或枚举敏感环境变量。

<a id="sensitive-field-registry"></a>
### 敏感字段注册表

下列名称及其大小写、连字符或下划线变体均按敏感字段处理；嵌套对象中的同名键同样适用：

```text
password
passwd
pwd
token
access_token
refresh_token
task_token
worker_token
auth_token
secret
shared_secret
client_secret
api_key
private_key
authorization
cookie
set-cookie
```

同时满足以下任一条件的字段，即使名称未列出，也按敏感字段处理：

- 值可直接用于认证、会话恢复、签名或权限绕过；
- 值包含完整凭据、私钥、Webhook 密钥或完整 `Authorization` header；
- 值是可长期访问或仍在有效期内的签名下载 URL；
- 值包含本地物理路径、内部堆栈或不应向当前调用方公开的内部标识。

扩展本注册表时，只在本节增加规范项；其他文档应链接本锚点，不复制或维护自己的敏感字段枚举。

<a id="sensitive-data-handling"></a>
### 外露与持久化规则

敏感值不得写入或原样返回以下位置：

```text
TaskItem.input_data
Result.data
Artifact metadata
Log.message / Log.fields
REST error.message / error.detail
Task / TaskItem error_message / error_detail
task_event.metadata
Worker reject_reason / message
协议 error_detail
通用 JSON 扩展字段
```

处理要求：

1. 非业务必需时删除字段；必须保留可观察性时只保存不可逆摘要、固定掩码或最小必要的非敏感片段。
2. 密码、Token、Cookie、密钥、完整认证头和私钥禁止保存到通用 JSON 字段。
3. `storage_key`、物理路径和下载 URL 的外露边界由对应文件资源契约定义，但任何有效签名和内部物理路径仍受本基线约束；Artifact `storage_key` 的对外返回边界由 [`ALIGN-003`](待对齐问题.md#align-003) 跟踪。
4. 脱敏必须在外露或入库前完成，不能依赖前端、日志查看器或下游消费者二次处理。
5. 删除或替换敏感值后，应保留 `request_id`、资源 ID、已登记错误码等非敏感关联标识，保证审计和排障能力。

<a id="security-logs-errors"></a>
### 日志、错误与诊断信息

1. SDK logger、Worker Runtime、Master 和脚本日志写入链路都必须应用 [敏感字段注册表](#sensitive-field-registry)。
2. `error.message` 面向调用方展示，`error.detail` 只提供脱敏后的结构化上下文；失败响应的完整契约见 [错误标识注册表](错误标识注册表.md#error-registry)。
3. 错误、拒绝和诊断信息不得包含内部堆栈、物理路径、下载签名、凭据或可用于绕过权限的内部标识。
4. 对未知对象或自由文本进行日志记录前，应执行键名过滤和常见凭据模式过滤；过滤失败时宁可省略值，不得原样落库。
5. 角色与资源操作权限矩阵尚未闭环，由 [`ALIGN-011`](待对齐问题.md#align-011) 跟踪；本基线只约束认证、凭据和外露，不裁决完整授权矩阵。
