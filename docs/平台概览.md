## 核心模型

JobOps 面向多种业务自动化场景，不绑定单一爬虫场景。核心资源关系为：

```text
Job Definition（作业定义） -> Task -> TaskItem
Job Definition（作业定义） -> Schedule -> ScheduleRun -> Task
Task -> Result / Artifact / Log
Source File -> Job Definition（作业定义） / Task / Schedule 的输入引用
```

|---|---|
| Job Definition（作业定义）/ Job Definition Version（作业定义版本） | [作业定义规范.md](作业定义规范.md#job-definition-model) |

<a id="platform-overview"></a>
## 项目定位

第一版系统定位为：

> 面向多种业务自动化场景的 JobOps 作业执行平台。

平台支持脚本驱动的数据读取、外部系统操作、状态查询、数据同步、附件处理和结果导出等场景。设计围绕可版本化的作业定义、可追溯的 Task、脚本上报的 TaskItem 以及统一输入输出资源展开，而不是围绕某一种业务动作建立专用模型。

本文件只说明这一产品边界；具体能力是否进入第一版由 [MVP范围.md](MVP范围.md#mvp-scope) 决定，具体行为由上表中的主题规范决定。

<a id="architecture-overview"></a>
## 总体执行链路

组件和数据流概览：

```text
Frontend / Admin / External API
        |
        | REST
        v
      Master
        |
        | gRPC Bidirectional Streaming
        v
      Worker
        |
        | Local Runtime API
        v
 Python Script + bot_sdk
```

运行上报链路：

```text
Python Script -> bot_sdk -> Worker Runtime -> Worker -> Master
```

组件边界：

| 组件 | 高层职责 | 详细规范 |
|---|---|---|
| Frontend / Admin / External API | 创建、查询和操作平台资源 | [REST 公共约定](API约定.md#rest-conventions)及各主题 API |
| Master | 对外 API、调度协调、状态裁定和持久化 | [Task 规范](Task执行规范.md#task-status)、[Worker 调度](Worker协议与运行时.md#worker-dispatch) |
| Worker | 接收 assignment、运行脚本、维护执行容量 | [Worker 协议](Worker协议与运行时.md#worker-protocol) |
| Worker Runtime / `bot_sdk` | 为本机脚本提供受控上报入口 | [Runtime / SDK](Worker协议与运行时.md#runtime-sdk) |

前端实时日志采用何种传输及其恢复语义，以 [Log API](结果-产物-日志.md#log-api) 为准；本文不重复定义。

完整的非规范性图示和走查路径见 [流程图与讨论材料.md](流程图与讨论材料.md)。

<a id="conclusion"></a>
## 第一版高层结论

> [非规范性摘要]
> 本节只用于快速回顾，不是新的规范来源；若摘要与主题规范存在差异，以 [文档目录.md](文档目录.md#document-guide) 指向的权威章节为准。

第一版围绕以下闭环实施：

```text
定义并发布 Job Definition Version（作业定义版本）
-> 创建 Task
-> Master 派发给 Worker
-> Worker 运行 Python Script
-> SDK 上报 TaskItem / Result / Artifact / Log
-> Master 持久化并裁定 Task 结果
-> 用户查询结果、日志和文件产物
```

实施范围与先后顺序见 [MVP 范围](MVP范围.md#mvp-scope)；状态与统计见 [Task 状态机](Task执行规范.md#task-status)和[统计规则](Task执行规范.md#task-statistics)；派发与运行时见 [Worker 协议](Worker协议与运行时.md#worker-protocol)；定时触发见 [Schedule 规范](Schedule调度规范.md#schedule-api)。
