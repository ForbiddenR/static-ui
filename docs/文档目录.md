# JobOps V1 文档目录

<a id="core-model"></a>
## 文档定位

本文件只负责总体入口、阅读路径、权威归属、共享规范导航和文档维护，不定义资源字段、状态、错误码或敏感字段。完整资源契约位于各主题文档；每类跨主题规则只由下表指定的一份支持文档负责。

核心关系：

```text
Job Definition（作业定义） -> Task -> TaskItem
Job Definition（作业定义） -> Schedule -> ScheduleRun -> Task
Task -> Result / Artifact / Log
Source File -> Job Definition（作业定义） / Task / Schedule 输入引用
```

平台总览见 [平台概览.md](平台概览.md#core-model)。

<a id="document-guide"></a>
## 阅读路径与规范优先级

推荐路径：

- 产品和验收：先看 [平台概览.md](平台概览.md)，再看 [Task执行规范.md](Task执行规范.md)、[Schedule调度规范.md](Schedule调度规范.md) 和 [MVP范围.md](MVP范围.md)。
- API 开发：先看 [API约定.md](API约定.md)，再看各主题资源 API。
- Master / Worker 开发：先看 [平台概览.md](平台概览.md#architecture-overview)、[Task执行规范.md](Task执行规范.md#task-status) 和 [Worker协议与运行时.md](Worker协议与运行时.md#worker-protocol)。
- SDK / 作业定义开发：先看 [术语与跨层标识.md](术语与跨层标识.md)、[Worker协议与运行时.md](Worker协议与运行时.md#runtime-sdk)、[源文件.md](./源文件.md#source-file-api)、[结果-产物-日志.md](结果-产物-日志.md#result-artifact-log-api) 和 [安全基线.md](安全基线.md)。

权威规则：

1. 每个资源的字段、状态机、资源 API、协议和持久化投影只由“主题规范”表中的对应文档定义；摘要、示例和导航不得覆盖主题契约。
2. REST 失败响应结构、HTTP 映射和所有错误标识只由 [错误标识注册表](错误标识注册表.md#error-registry) 登记；主题文档只说明已登记错误的业务触发条件和状态影响。
3. 敏感字段名称、识别规则和脱敏要求只由 [安全基线](安全基线.md#sensitive-field-registry) 定义；其他文档只能引用或描述局部应用。
4. [术语与跨层标识](术语与跨层标识.md) 只提供命名空间和权威导航；术语释义不能替代链接到的字段表、状态机或协议 payload。
5. 状态机和字段表优先于流程图和示例；持久化表是上层契约的投影，不反向定义 API。
6. MVP 只决定实施范围，不修改完整契约；跨层差异使用稳定 ID 登记到 [待对齐问题.md](待对齐问题.md#alignment-issues)，未决事项不得被静默裁决。
7. `流程图与讨论材料.md` 只用于架构走查和验收，不建立第二套规范。

## 文档维护规则

1. 每个资源契约和每类跨主题规则只能有一个权威位置；新增内容先确认归属，再修改对应权威文档。
2. 错误标识、敏感字段和待对齐事项分别只在各自注册表中新增；主题文档不得复制注册表形成并行清单。
3. 示例、流程图、术语释义、MVP 和数据表不能反向改写完整契约。
4. 发现跨层差异时使用稳定 `ALIGN-NNN` 登记到 [待对齐问题.md](待对齐问题.md#alignment-issues)，不在顺手编辑中替业务方裁决。
5. 根目录旧文件仅保留文件级兼容入口，当前规范以 `docs/` 为准；旧路径兼容范围见 [迁移映射.md](迁移映射.md#compatibility-scope)。
