<a id="result-artifact-log-api"></a>
## Result / Artifact / Log API 定稿

Result、Artifact、Log 分别解决三个不同问题：

| 类型 | 含义 | 示例 |
|---|---|---|
| `Result` | 结构化业务结果 | 审批提交结果、订单状态、抓取到的数据记录 |
| `Artifact` | 文件或大内容 | 截图、Excel 导出、PDF、上传回执 |
| `Log` | 运行过程和排错信息 | stdout、业务日志、Worker 日志 |

<a id="result-api"></a>
### Result API

Result 保存结构化业务结果。

#### 接口索引

| 方法 | 路径 | 用途 | 说明 |
|---|---|---|---|
| `GET` | `/api/results` | 分页查询 Result | 见 [Result 查询参数](#result-query) |
| `GET` | `/api/results/{result_id}` | 查询 Result 详情 | 返回完整 Result 对象 |
| `GET` | `/api/tasks/{task_id}/results` | 查询某个 Task 的 Result | 见 [Result 查询参数](#result-query) |
| `GET` | `/api/tasks/{task_id}/items/{item_id}/results` | 查询某个 TaskItem 的 Result | 见 [Result 查询参数](#result-query) |
| `POST` | `/api/tasks/{task_id}/results/export` | 创建 Task Result 导出 | 见 [导出 Result](#result-export) |

#### 共享返回对象：Result

以下字段表同时适用于 Result 列表接口、Result 详情接口以及 Task/TaskItem 关联查询接口。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `id` | string | 是 | Result ID |
| `task_id` | string | 是 | 所属 Task |
| `task_item_id` | string | 否 | 所属 TaskItem；Task 级结果为空 |
| `bot_id` | string | 是 | 冗余 Job Definition ID |
| `type` | string | 是 | 结果类型，例如 `approval_result`、`crawl_record`、`status_snapshot` |
| `key` | string | 否 | 业务 key，例如外部订单号、URL、Excel 行号 |
| `data` | object | 是 | 结构化结果数据，禁止存放大文件内容 |
| `idempotency_key` | string | 否 | SDK 上报幂等键，同一 Task 内唯一；各入口作用域边界由 [`ALIGN-013`](待对齐问题.md#align-013) 跟踪 |
| `created_at` | string | 是 | 创建时间 |
| `updated_at` | string | 是 | 更新时间 |

<a id="result-query"></a>
#### Result 查询参数

以下 Query 字段适用于 `GET /api/results`、`GET /api/tasks/{task_id}/results` 和 `GET /api/tasks/{task_id}/items/{item_id}/results`。路径参数已经提供的过滤条件不需要重复传入。

| Query 字段 | 类型 | 说明 |
|---|---|---|
| `task_id` | string | 按 Task 过滤 |
| `task_item_id` | string | 按 TaskItem 过滤 |
| `bot_id` | string | 按 Job Definition 过滤 |
| `type` | string | 按结果类型过滤 |
| `key` | string | 按业务 key 精确查询 |
| `q` | string | 搜索 key 或 data 摘要 |

<a id="result-export"></a>
#### 导出 Result

```http
POST /api/tasks/{task_id}/results/export
```

请求字段：

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---:|---|---|
| `format` | string | 是 | - | `csv`、`xlsx`、`json` |
| `type` | string | 否 | `null` | 只导出某类 Result |
| `fields` | array<string> | 否 | 全部字段 | 指定导出字段 |
| `filters` | object | 否 | `{}` | 导出过滤条件 |

响应返回**导出创建回执**，不是完整 Artifact 共享对象：

```json
{
  "data": {
    "artifact_id": "artifact_export_xxx",
    "status": "created"
  }
}
```

调用方使用 `artifact_id` 查询 [Artifact 详情](#artifact-api)或调用下载接口；本回执不替代 Artifact 元数据响应，也不据此扩展 Artifact 字段契约。

<a id="artifact-api"></a>
### Artifact API

Artifact 保存文件和大内容。下载接口返回文件内容；列表、详情和关联查询返回 Artifact 元数据。`storage_key` 是否属于对外共享对象仍存在跨层冲突，由 [`ALIGN-003`](待对齐问题.md#align-003) 跟踪，本文件不在本次优化中裁决。

#### 接口索引

| 方法 | 路径 | 用途 | 说明 |
|---|---|---|---|
| `GET` | `/api/artifacts` | 分页查询 Artifact | 返回 Artifact 元数据 |
| `GET` | `/api/artifacts/{artifact_id}` | 查询 Artifact 详情 | 返回完整 Artifact 元数据 |
| `GET` | `/api/artifacts/{artifact_id}/download` | 下载 Artifact 文件内容 | 返回二进制响应 |
| `GET` | `/api/tasks/{task_id}/artifacts` | 查询 Task 的 Artifact | 返回 Artifact 元数据列表 |
| `GET` | `/api/tasks/{task_id}/items/{item_id}/artifacts` | 查询 TaskItem 的 Artifact | 返回 Artifact 元数据列表 |

#### 共享返回对象：Artifact

以下字段表适用于 Artifact 列表、详情和关联查询接口；下载接口返回文件内容，不返回此对象作为主体。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `id` | string | 是 | Artifact ID |
| `task_id` | string | 是 | 所属 Task |
| `task_item_id` | string | 否 | 所属 TaskItem；Task 级文件为空 |
| `bot_id` | string | 是 | 冗余 Job Definition ID |
| `name` | string | 是 | 文件展示名 |
| `type` | string | 是 | 文件类型，例如 `screenshot`、`export`、`attachment`、`debug_bundle` |
| `content_type` | string | 是 | MIME 类型，例如 `image/png` |
| `size` | integer | 是 | 文件大小，字节 |
| `storage_backend` | string | 是 | 存储后端，第一版为 `local` |
| `storage_key` | string | 是 | 当前字段表保留的后端内部 key；是否应出现在对外响应尚未对齐 |
| `checksum` | string | 否 | 文件校验值，建议 `sha256:<hex>` |
| `idempotency_key` | string | 否 | SDK 上报幂等键 |
| `created_at` | string | 是 | 创建时间 |
| `updated_at` | string | 是 | 更新时间 |

> [待对齐｜不在本次范围]
> 上表保留既有 `storage_key` 字段，而下载与安全边界要求不直接暴露内部定位信息。该冲突统一跟踪于 [`ALIGN-003`](待对齐问题.md#align-003)；在正式决策前，不从任一侧推导新的对外契约。

Artifact type 推荐值：

| 值 | 含义 |
|---|---|
| `screenshot` | 截图 |
| `download` | 脚本下载到的业务文件 |
| `upload_receipt` | 外部系统上传/提交回执 |
| `export` | Result 导出文件 |
| `debug_bundle` | 失败现场、HAR、日志包等调试文件 |
| `custom` | 自定义文件 |

第一版存储为 `local`；后续可扩展 `s3`、`oss`、`minio`、`cos`。

下载规则：

```text
GET /api/artifacts/{artifact_id}/download 必须鉴权
下载时后端根据权限校验用户是否可访问对应 Task/Job Definition
响应头设置 Content-Type 和 Content-Disposition
不直接返回可长期访问的 storage path
```

<a id="log-api"></a>
### Log API

Log 保存运行过程和排错信息。

#### 接口索引

| 方法 | 路径 | 用途 | 说明 |
|---|---|---|---|
| `GET` | `/api/logs` | 分页查询全局日志 | 需要较高权限，默认按时间倒序 |
| `GET` | `/api/tasks/{task_id}/logs` | 查询 Task 日志 | 返回历史日志列表 |
| `GET` | `/api/tasks/{task_id}/items/{item_id}/logs` | 查询 TaskItem 日志 | 返回关联日志列表 |
| `GET` | `/api/tasks/{task_id}/logs/stream` | 订阅 Task 实时日志 | SSE 长连接 |

实时日志第一版优先使用 SSE。

#### 共享返回对象：Log

以下字段表适用于历史日志查询接口和 SSE 的 `log` 事件；SSE 的 `task_status`、`done` 事件使用各自的事件字段。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `id` | string | 是 | Log ID |
| `task_id` | string | 是 | 所属 Task |
| `task_item_id` | string | 否 | 所属 TaskItem |
| `bot_id` | string | 是 | 冗余 Job Definition ID |
| `worker_id` | string | 否 | 产生日志的 Worker |
| `level` | string | 是 | 日志级别 |
| `message` | string | 是 | 日志正文，必须脱敏 |
| `fields` | object | 否 | 结构化字段，必须脱敏 |
| `source` | string | 是 | 日志来源 |
| `seq` | integer | 否 | Task 内单调递增序号，用于前端增量加载 |
| `created_at` | string | 是 | 日志时间 |

level：

| 值 | 含义 |
|---|---|
| `debug` | 调试日志 |
| `info` | 普通信息 |
| `warning` | 警告 |
| `error` | 错误 |

source：

| 值 | 含义 |
|---|---|
| `script` | Python 脚本输出或 SDK 日志 |
| `worker` | Worker 执行器日志 |
| `runtime` | Worker Runtime 日志 |
| `master` | Master 调度和状态日志 |
| `system` | 系统生成日志 |

查询日志支持：

| Query 字段 | 类型 | 说明 |
|---|---|---|
| `level` | string | 按级别过滤 |
| `source` | string | 按来源过滤 |
| `task_item_id` | string | 按 TaskItem 过滤 |
| `since_seq` | integer | 只返回某个 seq 之后的日志 |
| `limit` | integer | 返回条数，默认 200，最大 1000 |
| `q` | string | 搜索 message |

SSE 事件：

```http
GET /api/tasks/{task_id}/logs/stream
```

事件建议：

```text
event: log
data: {"id":"log_xxx","seq":12,"level":"info","message":"started"}

event: task_status
data: {"task_id":"task_xxx","status":"running"}

event: done
data: {"task_id":"task_xxx","status":"success"}
```

> [待对齐｜不在本次范围]
> Log API 已使用 `seq`、`since_seq`，SSE 恢复还涉及 `Last-Event-ID`，但 `logs` 持久化字段和唯一约束尚未完整承载这些语义。问题由 [`ALIGN-004`](待对齐问题.md#align-004) 跟踪；本文件保留现状，不新增字段、约束或恢复算法。

日志保留策略建议：

```text
第一版可写数据库
默认每个 Task 最多保留 10,000 行或保留 7 天
超过限制时优先丢弃 debug 日志
error 日志应尽量保留
```

日志内容、结构化字段、错误详情和上下文 metadata 必须按 [敏感字段与脱敏规则](安全基线.md#sensitive-data-handling) 处理；本文件不重复维护敏感字段注册表。

<a id="persistence-map"></a>
## 持久化映射说明

`results`、`artifacts` 和 `logs` 是本文件定义资源的持久化投影。`source_files` 已迁移至 [源文件.md#persistence-map](./源文件.md#persistence-map)。数据表不反向改写 API；Artifact `storage_key` 由 [`ALIGN-003`](待对齐问题.md#align-003) 跟踪，Log `seq` / SSE 恢复缺口由 [`ALIGN-004`](待对齐问题.md#align-004) 跟踪。

### results

字段：

```text
id
task_id
task_item_id
bot_id
type
key
data
idempotency_key
created_at
updated_at
```

索引：

```text
index(task_id)
index(task_item_id)
index(bot_id, created_at)
index(type)
index(key)
index(created_at)
unique(task_id, idempotency_key)
```

### artifacts

字段：

```text
id
task_id
task_item_id
bot_id
name
type
content_type

storage_backend

updated_at
```

索引：

```text
index(task_id)
index(task_item_id)
index(bot_id, created_at)
index(type)
index(content_type)
index(created_at)
unique(task_id, idempotency_key)
```

### logs

字段：

```text
id
task_id
task_item_id
bot_id
worker_id
level
message
fields
source
created_at
```

索引：

```text
index(task_id, created_at)
index(task_item_id, created_at)
index(bot_id, created_at)
index(worker_id, created_at)
index(level, created_at)
```

> `logs` 表仍未补入 `seq` 及相关唯一约束；这项缺口由 [`ALIGN-004`](待对齐问题.md#align-004) 跟踪，本节不自行补齐。
