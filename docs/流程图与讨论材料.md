## 系统上下文图

```mermaid
flowchart LR
    User[业务用户] -->|REST| Master
    Admin[管理员 / 运维] -->|REST| Master
    External[外部系统] -->|REST + API Token| Master
    Browser[管理前端] <-->|REST / SSE| Master

    Master[(Master)] <-->|gRPC 双向 Streaming| WorkerA[Worker A]
    Master <-->|gRPC 双向 Streaming| WorkerB[Worker B]

    WorkerA --> RuntimeA[Worker Runtime]
    WorkerB --> RuntimeB[Worker Runtime]
    RuntimeA <-->|Local API| ScriptA[Python Script + bot_sdk]
    RuntimeB <-->|Local API| ScriptB[Python Script + bot_sdk]

    Master --> DB[(关系数据库)]
    Master --> Storage[(Source File / Artifact 存储)]
    WorkerA --> Storage
    WorkerB --> Storage
```

走查重点：外部调用只进入 Master；脚本通过本机 Runtime 上报；Master 与 Worker 的控制面边界见 [Worker 协议](Worker协议与运行时.md#worker-protocol)，安全边界见 [安全基线](安全基线.md#security-baseline)。

<a id="execution-walkthrough"></a>
## Task 执行走查

```mermaid
sequenceDiagram
    autonumber
    actor Caller as 用户 / 外部系统
    participant API as Master REST API
    participant Scheduler as Master Scheduler
    participant Worker as Worker
    participant Runtime as Worker Runtime
    participant Script as Python Script + bot_sdk
    participant Store as Database / Storage

    Caller->>API: 准备 BotVersion、输入并创建 Task
    API->>Store: 持久化 Task
    API-->>Caller: 返回 Task

    Scheduler->>Worker: 派发 assignment
    Worker-->>Scheduler: 接受并启动
    Worker->>Script: 运行脚本

    loop 业务执行
        Script->>Runtime: 上报 TaskItem / Result / Artifact / Log
        Runtime->>Worker: 汇聚上报
        Worker->>Scheduler: 发送运行报告
        Scheduler->>Store: 幂等持久化
    end

    Script-->>Worker: 进程结束
    Worker->>Scheduler: 上报执行结束
    Scheduler->>Store: 按权威规则裁定并保存 Task 结果
    Caller->>API: 查询状态与输出
```

本图只展示主链路。Task 终态裁定、取消、超时和统计冲突见 [Task 状态机](Task执行规范.md#task-status)；Runtime 报告结构见 [Worker Runtime / SDK](Worker协议与运行时.md#runtime-sdk)。

<a id="dispatch-handshake"></a>
## Task 派发握手走查

```mermaid
sequenceDiagram
    autonumber
    participant S as Master Scheduler
    participant DB as Database
    participant W as Worker

    S->>DB: 选择可派发 Task 并建立 assignment / reservation
    S->>W: AssignTask

    alt Worker 拒绝或 Ack 未成立
        W-->>S: 拒绝或未在 deadline 内确认
        S->>DB: 使旧 assignment 失效并回收预约
        S->>DB: 按权威规则重新进入待派发路径
    else Worker 接受
        W-->>S: TaskAck accepted
        W->>W: 准备输入、Runtime 和进程
        alt Start 未成立
            S->>DB: 使旧 assignment 失效并回收预约
            S-->>W: AbortAssignment
        else 进程成功启动
            W-->>S: TaskStarted
            S->>DB: 提交运行阶段状态和容量占用
        end
    end
```

走查时重点核对 assignment、会话、deadline 和 fencing，但不在本文复制判定算法或竞态矩阵。完整规则见 [Worker 调度](Worker协议与运行时.md#worker-dispatch)及 [Task Ack / Start 规则](Task执行规范.md#task-status)。

<a id="schedule-walkthrough"></a>
## Schedule 触发走查

```mermaid
flowchart TD
    Plan[按 cron 与 timezone 计算触发时点] --> Run[创建或记录 ScheduleRun]
    Run --> Enabled{Schedule 与目标 Bot 是否可触发?}
    Enabled -- 否 --> NoTask[记录未创建 Task 的触发结果]
    Enabled -- 是 --> Overlap{按 overlap / missed run 规则判断}
    Overlap -- 本次不执行 --> NoTask
    Overlap -- 本次执行 --> Create[创建 Task]
    Create --> Pending[Task 进入执行链路]
    Pending --> Dispatch[由 Worker 调度规则派发]
```

本图不展开枚举、jitter 算法或补跑细节。完整触发和 ScheduleRun 语义见 [Schedule 规范](Schedule调度规范.md#schedule-api)，第一版实施裁剪见 [MVP 范围](MVP范围.md#mvp-scope)。

<a id="output-walkthrough"></a>
## Result、Artifact 与 Log 输出走查

```mermaid
flowchart LR
    Script[Python Script] --> SDK[bot_sdk]
    SDK --> Runtime[Worker Runtime]

    Runtime -->|结构化业务数据| Result[Result 上报]
    Runtime -->|文件或大内容| Artifact[Artifact 上传 / 元数据上报]
    Runtime -->|运行与诊断信息| Log[Log 批次]

    Result --> Worker[Worker]
    Artifact --> Worker
    Log --> Worker
    Worker --> Master[Master]

    Master --> DB[(Result / Artifact / Log 元数据)]
    Master --> Storage[(Artifact 内容存储)]
    Browser[Frontend] -->|查询元数据 / 日志| Master
    Browser -->|受控下载| Master
    Master --> Storage
```

走查重点：Result、Artifact、Log 的职责不同，Source File 不属于输出资源。Artifact `storage_key` 的对外边界由 [`ALIGN-003`](待对齐问题.md#align-003) 跟踪，Log `seq` / SSE 恢复持久化由 [`ALIGN-004`](待对齐问题.md#align-004) 跟踪；本文不选择任何一侧。当前主题契约见 [结果-产物-日志.md](结果-产物-日志.md#result-artifact-log-api)。

<a id="acceptance-walkthrough"></a>
## 端到端验收走查

```mermaid
flowchart LR
    A[发布可执行 BotVersion] --> B[准备 Source File 或参数]
    B --> C[创建 Task]
    C --> D[Worker 接受并启动]
    D --> E[脚本上报 TaskItem / Result / Artifact / Log]
    E --> F[Master 持久化并裁定 Task]
    F --> G[前端收到状态与日志更新]
    G --> H[查询 Result / Artifact 元数据]
    H --> I[通过受控接口下载 Artifact]
```

验收材料应从权威规范生成，而不是从本图补充业务规则。至少覆盖以下走查类别：

- 正常执行和不同 TaskItem 统计组合；
- `pending`、派发中和运行中的取消；
- 整体超时及迟到消息；远程进程终止闭环按 [`ALIGN-006`](待对齐问题.md#align-006) 跟踪；
- Worker 在派发前后离线的不同处理；
- retry / rerun 的新 Task 与历史追溯；
- Schedule 基础触发和重叠裁剪；
- SSE 断线恢复、输出查询与下载权限；
- assignment fencing 和旧消息丢弃。

具体期望结果分别取自 [Task 规范](Task执行规范.md#task-status)、[Worker 规范](Worker协议与运行时.md#worker-dispatch)、[Schedule 规范](Schedule调度规范.md#schedule-api)、[输出资源规范](结果-产物-日志.md#result-artifact-log-api)和[安全基线](安全基线.md#security-baseline)。如验收依赖尚未闭环的跨层语义，应链接 [待对齐问题.md](待对齐问题.md#alignment-issues)，而不是在本文创建本地问题清单。流程图治理约束由 [`ALIGN-007`](待对齐问题.md#align-007) 持续跟踪。
