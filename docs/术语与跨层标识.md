## 状态命名空间与共享导航

### 状态命名空间

文档中的 `status` 必须结合所属资源解释。即使字面值相同，也不能跨命名空间复用枚举或迁移规则。本表只导航到唯一权威，不在此重新登记状态值。

| 状态字段 | 命名空间说明与唯一权威 |
|---|---|
| `Task.status` | Task 调度与执行状态，见 [Task 状态机](Task执行规范.md#task-status) |
| `TaskItem.status` | 单项处理状态，见 [TaskItem 状态机](Task执行规范.md#task-item-status) |
| `Bot.status` | 作业定义是否可被使用的资源状态；`Bot.status` 是 V1 兼容字段，见 [作业定义 API](作业定义规范.md#job-definition-api) |
| `BotVersion.status` | 作业定义版本的 `draft` / `published` 生命周期；`BotVersion.status` 是 V1 兼容字段，见 [作业定义 API](作业定义规范.md#job-definition-api) |
| `Worker.status` | Worker 的 `online` / `offline` / `disabled` 管理状态，见 [Worker 管理 REST](Worker协议与运行时.md#worker-rest-api) |
| `Schedule.status` | Schedule 的启停状态，见 [Schedule API](Schedule调度规范.md#schedule-api) |
| `ScheduleRun.status` | 一次调度触发决策或执行关联状态，唯一权威见 [Schedule API](Schedule调度规范.md#schedule-api) |
| `RunningTaskRef.local_status` | Worker 本地进程阶段，见 [Worker 协议](Worker协议与运行时.md#worker-protocol)；不是 `Task.status` |

### 统一术语表与错误标识导航

> [本节角色]
> 本节给出跨领域名称的导航性释义，帮助读者选择正确命名空间。释义本身不是契约；完整字段、状态迁移、协议 payload 和持久化语义只以“唯一权威 / 使用边界”所列章节为准。REST 错误标识见 [错误标识注册表](错误标识注册表.md#error-registry)，敏感字段见 [安全基线](安全基线.md#sensitive-field-registry)。

#### 领域与执行实体

| 术语 | 导航性释义 | 唯一权威 / 使用边界 |
|---|---|---|
| `Master` | 对外提供 REST、执行调度、Worker 协调、Task 终态裁定和持久化的平台控制方 | [总体执行链路](平台概览.md#architecture-overview)、[Task 状态机](Task执行规范.md#task-status)、[Worker 协议](Worker协议与运行时.md#worker-protocol) |
| Job Definition（作业定义） | 自动化脚本定义，不是一次执行；V1 契约中的资源名仍为 `Bot` | [作业定义模型](作业定义规范.md#job-definition-model)；REST 投影见 [作业定义 API](作业定义规范.md#job-definition-api) |
| Job Definition Version（作业定义版本） | 作业定义执行行为的版本；`published` 表示已发布，`is_current=true` 才表示当前版本；V1 契约中的资源名仍为 `BotVersion` | [作业定义 API](作业定义规范.md#job-definition-api) |
| `Task` | 作业定义的一次 Python 脚本执行，也是第一版调度单元 | [Task 模型](Task执行规范.md#task-model)、[Task 状态机](Task执行规范.md#task-status)、[Task API](Task执行规范.md#task-api) |
| `TaskItem` | 脚本动态上报的执行明细，是观测和统计单元，不是第一版调度单元 | [Task 模型](Task执行规范.md#task-model)、[TaskItem 状态机](Task执行规范.md#task-item-status)、[TaskItem API](Task执行规范.md#task-item-api) |
| `Worker` | 主动连接 Master、接收 assignment 并运行 Task 的执行节点 | [总体执行链路](平台概览.md#architecture-overview)、[Worker 协议](Worker协议与运行时.md#worker-protocol) |
| `system_tags` / 系统标签 | Worker 注册上报、控制台只读的节点标签 | [Worker 管理 REST](Worker协议与运行时.md#worker-rest-api) |
| `user_tags` / 用户标签 | 运维在网站可编辑的节点标签；不得与系统标签重名 | [Worker 管理 REST](Worker协议与运行时.md#worker-rest-api) |
| `runtimes` / 运行时 | Worker 注册上报的脚本运行时列表（如 `python3.12`）；系统字段，控制台只读；用于 `requirements.runtime` 匹配；**不是**用户标签，也不同于进程 `version` | [Worker 管理 REST](Worker协议与运行时.md#worker-rest-api)、[Worker 协议 Hello](Worker协议与运行时.md#worker-protocol) |
| `version`（Worker） | Worker 进程版本（如 `workerd/1.4.2`），不是 Python 解释器版本 | [Worker 管理 REST](Worker协议与运行时.md#worker-rest-api) |
| `Worker Pool` | 显式成员组成的投放范围；缩小调度候选集合，不覆盖节点容量 | [Worker Pool](Worker协议与运行时.md#worker-pool)、[Worker 调度 / Placement](Worker协议与运行时.md#worker-dispatch) |
| `placement` / 投放目标 | `auto`、工作池或节点 pin；字段为 `target_pool_id` / `target_worker_id`，创建时冻结 | [Worker 调度](Worker协议与运行时.md#worker-dispatch)、[Schedule API](Schedule调度规范.md#schedule-api)、[Task 模型](Task执行规范.md#task-model) |
| `Worker Runtime` | Worker 本机代理，向 Python SDK 提供本地 API 并汇聚业务上报 | [Runtime / SDK](Worker协议与运行时.md#runtime-sdk) |
| `bot_sdk` | 作业定义脚本使用的平台 SDK；只访问 Worker Runtime，不直接访问 Master；名称是 V1 兼容契约 | [Runtime / SDK](Worker协议与运行时.md#runtime-sdk)、[安全基线](安全基线.md#security-baseline) |
| `Schedule` | 定时触发规则，不是执行记录 | [Schedule API](Schedule调度规范.md#schedule-api) |
| `ScheduleRun` | 一次调度触发决策记录；被跳过或触发失败时可以没有对应 Task | [Schedule API](Schedule调度规范.md#schedule-api) |
| `SourceFile` / Source File | 用户或系统上传的输入类文件及其元数据，是脚本包和任务输入的统一入口 | [Source File 契约](./源文件.md#source-file-api)、[Source File 持久化映射](./源文件.md#persistence-map) |
| `Result` | Task 或 TaskItem 产生的结构化业务结果，不保存大文件内容 | [Result API](结果-产物-日志.md#result-api)、[输出与文件持久化映射](结果-产物-日志.md#persistence-map) |
| `Artifact` | Task 运行产生的文件或大内容；API 返回元数据，内容通过鉴权下载接口获取 | [Artifact API](结果-产物-日志.md#artifact-api)、[输出与文件持久化映射](结果-产物-日志.md#persistence-map) |
| `Log` | Task、TaskItem、Worker 或 Runtime 产生的过程和排错记录 | [Log API](结果-产物-日志.md#log-api)、[输出与文件持久化映射](结果-产物-日志.md#persistence-map) |
| `TaskEvent` | `Task.status` 迁移和平台 Task 事件的审计记录，不记录其他资源状态 | [Task 持久化映射](Task执行规范.md#persistence-map) |

#### 状态与执行概念

| 术语 | 导航性释义 | 唯一权威 / 使用边界 |
|---|---|---|
| Task 终态 | `success`、`partial_success`、`failed`、`canceled`、`timeout` | [Task 状态机](Task执行规范.md#task-status) |
| 活跃 Task | `pending`、`dispatching`、`running`、`canceling`；主要用于调度和 overlap 判断 | [Task 状态机](Task执行规范.md#task-status)、[Schedule API](Schedule调度规范.md#schedule-api) |
| `partial_success` | 脚本正常结束后，TaskItem 业务结果部分失败 | [Task 状态机](Task执行规范.md#task-status) |
| Task 整体 `timeout` | 已运行 Task 的整体执行超时，是 `Task.status` 终态 | [Task 状态机](Task执行规范.md#task-status) |
| TaskItem 单项 `timeout` | 单个 TaskItem 处理超时，是 `TaskItem.status` 终态 | [TaskItem 状态机](Task执行规范.md#task-item-status) |
| `queue_entered_at` | 当前一轮进入 `pending` 队列的时间，是 FIFO 和 priority aging 的基准；真正重新入队时重置 | [Worker 调度规则](Worker协议与运行时.md#worker-dispatch) |
| `next_dispatch_at` | 下一次允许自动派发的时间；为 `null` 表示暂停自动派发、等待人工处置 | [Worker 调度规则](Worker协议与运行时.md#worker-dispatch) |
| `dispatch_attempts` | 已成功建立 assignment 和容量预约的自动派发次数；扫描到无候选 Worker 不计数 | [Worker 调度规则](Worker协议与运行时.md#worker-dispatch) |
| `ack_deadline_at` | 当前 assignment 必须收到合法 `TaskAck` 的截止时间；不是 Task 整体超时 | [Task 状态机](Task执行规范.md#task-status)、[Worker 协议](Worker协议与运行时.md#worker-protocol) |
| `start_deadline_at` | accepted assignment 必须收到合法 `TaskStarted` 的截止时间；不是 Task 整体超时 | [Task 状态机](Task执行规范.md#task-status)、[Worker 协议](Worker协议与运行时.md#worker-protocol) |
| `dispatch_deadline_at` | 旧版对 Ack / Started 截止的汇总名称；新实现以 `ack_deadline_at`、`start_deadline_at` 为准 | [Task 状态机](Task执行规范.md#task-status) |
| `effective_priority` | 调度器根据持久化 `priority` 和等待时长计算的只读排序值，不回写 `Task.priority` | [Worker 调度规则](Worker协议与运行时.md#worker-dispatch) |
| dispatch reservation | Master 为一个有效 `dispatching` assignment 预约的 Worker 槽位；Ack 后、Started 前仍占用 | [Worker 调度规则](Worker协议与运行时.md#worker-dispatch) |
| `Task.statistics` | TaskItem 聚合统计读模型，也是脚本正常完成时的终态裁定输入 | [Task 状态机](Task执行规范.md#task-status)、[统计规则](Task执行规范.md#task-statistics)、[Task API](Task执行规范.md#task-api) |
| `bot_snapshot` | Task 创建时冻结的作业定义执行快照，用于历史可追溯；字段名是 V1 兼容契约 | [Task API](Task执行规范.md#task-api)、[作业定义 API](作业定义规范.md#job-definition-api) |

#### 协议与一致性标识

| 术语 | 导航性释义 | 唯一权威 / 使用边界 |
|---|---|---|
| `message_id` | 单条传输消息的去重键 | [Worker 协议](Worker协议与运行时.md#worker-protocol) |
| `session_id` | 当前 gRPC Connect 会话的隔离键；旧会话消息不得写入当前会话 | [Worker 协议](Worker协议与运行时.md#worker-protocol) |
| `assignment_id` | 一次 Task 派发实例 ID，也是 fencing 主键 | [Task 状态机](Task执行规范.md#task-status)、[Worker 协议](Worker协议与运行时.md#worker-protocol) |
| `command_id` | `CancelTask` 与 `CancelResult` 的命令配对键 | [Worker 协议](Worker协议与运行时.md#worker-protocol) |
| `idempotency_key` | 创建请求或 Task 内业务写入的去重键；具体唯一域随入口而异，不代替消息去重或 assignment fencing | 各入口契约见 [Source File](./源文件.md#source-file-api)、[Task API](Task执行规范.md#task-api)、[Runtime / SDK](Worker协议与运行时.md#runtime-sdk) 和 [输出资源](结果-产物-日志.md#result-artifact-log-api)；跨入口作用域与存储由 [`ALIGN-013`](待对齐问题.md#align-013) 跟踪 |
| fencing | Master 只接受当前 `assignment_id` 的消息和写入，拒绝旧派发串写 | [Task 状态机](Task执行规范.md#task-status)、[Worker 协议](Worker协议与运行时.md#worker-protocol) |
| assignment lease | 派发前由当前 assignment、Ack / Start deadline 和 abort 状态共同构成的启动许可；lease 失效后 Worker 不得启动或继续准备该 assignment | [Task 状态机](Task执行规范.md#task-status)、[Worker 协议](Worker协议与运行时.md#worker-protocol) |
| `abort_assignment` / `AbortAssignment` | Master 宣告 assignment 已失效的对账动作 / 控制消息；用于阻止旧 assignment 启动或继续执行，不等同于用户取消 | [Worker 协议](Worker协议与运行时.md#worker-protocol) |
| `TASK_TOKEN` | 当前 Task 的短期、本机 Runtime 访问令牌，不具备 Master 管理权限 | [Worker 协议](Worker协议与运行时.md#worker-protocol)、[Runtime / SDK](Worker协议与运行时.md#runtime-sdk)、[安全基线](安全基线.md#security-baseline) |
| `worker_token` / `shared_secret` | Worker 建立 gRPC 会话使用的认证凭据 | [Worker 协议](Worker协议与运行时.md#worker-protocol)、[安全基线](安全基线.md#security-baseline) |

| storage path | 本地物理存储路径，只能内部使用，不作为对外 API 字段 | [Source File 契约](./源文件.md#source-file-api)、[Artifact API](结果-产物-日志.md#artifact-api) |
| 下载 URL | 受鉴权或短期签名保护的内容获取入口，不是持久化定位标识 | [Source File 契约](./源文件.md#source-file-api)、[Artifact API](结果-产物-日志.md#artifact-api) |
| 旁路上传 | Artifact 二进制不进入 `RuntimeReportBatch`，协议流只传元数据和内部存储定位 | [Worker 协议](Worker协议与运行时.md#worker-protocol) |
| 软删除 | 保留资源 ID 和历史元数据，通过状态阻止后续使用，并允许后续物理清理 | [Source File 契约](./源文件.md#source-file-api) |
| 持久化映射 | [持久化映射](文档目录.md#persistence-map) 对领域、API 和协议对象的存储投影，不反向定义上层语义 | [持久化映射](文档目录.md#persistence-map) |

<a id="unified-terms"></a>
## 统一术语与易混淆概念

本节只用于选择正确的资源名和命名空间。具体枚举、字段及行为必须继续查看前文矩阵链接的唯一权威。

### 易混淆术语对照

| 容易混淆的术语 | 导航性区别 |
|---|---|
| Job Definition（作业定义）/ Job Definition Version（作业定义版本）/ current version | 作业定义是资源和脚本定义；作业定义版本是执行行为版本；`published` 不等于 current，同一作业定义只有 `is_current=true` 的版本是当前版本。V1 机器契约仍使用 Bot / BotVersion 名称。 |
| Task / TaskItem | Task 是一次脚本执行和调度单元；TaskItem 是脚本产生的业务明细和观测单元 |
| `Task.status` / `TaskItem.status` / `RunningTaskRef.local_status` | 分别属于 Task 状态机、TaskItem 状态机和 Worker 本地进程阶段，不得互相回写或复用迁移规则 |
| retry / rerun | retry 面向失败补救；rerun 面向任意终态的全量重新执行 |
| Schedule / ScheduleRun / Task | 分别是触发规则、一次触发决策和一次真实脚本执行 |
| Source File / Result / Artifact / Log | 分别是输入文件、结构化业务结果、输出文件或大内容、过程与排错记录 |
| `message_id` / `idempotency_key` / `assignment_id` / `session_id` | 分别负责消息去重、业务写入幂等、派发 fencing 和连接会话隔离 |
| `storage_key` / storage path / 下载 URL | 分别是内部逻辑定位键、本地物理路径和受控内容获取入口 |
| Worker `disabled` / `offline` | `disabled` 是管理员禁止新派发；`offline` 是连接或心跳失效 |
| `ITEM_NOT_FINALIZED` / `ITEMS_NOT_FINALIZED` | 前者是 SDK 产生的单个 TaskItem 执行错误；后者是 Master 裁定 Task 时发现仍有未终态 TaskItem 的 Task 执行错误 |
